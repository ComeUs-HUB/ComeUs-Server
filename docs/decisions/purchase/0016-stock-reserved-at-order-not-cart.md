# ADR 0016 — 재고 점유는 주문 생성에서 시작하고 장바구니는 점유하지 않는다

- 상태: 채택 (0025가 보강)
- 일자: 2026-10-02
- 관련: [domains/purchase/](../../domains/purchase/README.md), [ADR 0015](../catalog/0015-no-stock-quantity-in-public-response.md)

## 맥락

Phase 4 착수 전에 재고를 **어디서 검사하고 어디서 점유하는가**를 정해야 했다.

[ADR 0015](../catalog/0015-no-stock-quantity-in-public-response.md)가 공개 상품 응답에서
`stockQuantity`를 뺐으므로 **FE는 수량 상한을 모른다.** 선반영된 에러 코드는 둘이고 둘 다 409다 —
담기의 `CT002 CART_QUANTITY_EXCEEDED`, 상품의 `P002 OUT_OF_STOCK`.

## 결정

**검사는 담기와 주문 생성 두 곳에서 하고, 점유는 주문 생성 한 곳에서만 한다.**

| | 담기 `CT002` | 주문 생성 `P002` |
|---|---|---|
| 목적 | 즉시 피드백(UX) | **불변식 방어**(재고 ≥ 0) |
| 재고 변경 | 없음, 읽기만 | 차감 = 점유 |
| 락·동시성 | 없음. 경합을 무시한다 | 동시성 제어의 대상 |
| 틀렸을 때 | 손해 없음 — 주문에서 다시 걸린다 | 음수 재고 = 버그 |
| 주체 | `CartService` | `Product.decreaseStock()` |

- 담기 검사 대상은 **합산 후 수량(기존 + 요청)**이다 — 1개씩 나눠 담아 재고를 넘기는 경로를 막는다
- 점유는 주문 생성(`PENDING`)의 차감이다. `CANCELLED`로 가는 **모든 전환**이 복구한다
- 장바구니 조회는 구매 가능 여부를 **불리언으로만** 담는다. 수량을 담으면 회원가입만으로
  재고를 읽을 수 있어 [ADR 0015](../catalog/0015-no-stock-quantity-in-public-response.md)의 방어가 얕아진다

### 담기 검사는 보장이 아니다

담기와 주문 사이는 며칠일 수 있어 담기 시점의 판정은 그때 이미 무효다.
`Product.decreaseStock()`의 `P002`가 **유일한 방어선**이며, 담기에서 걸렀다는 이유로
주문에서 생략하지 않는다. 이 구분을 적어두지 않으면 주문 측 검사를 빼는 버그가 난다.

## 배제한 대안과 근거

| 대안 | 배제 이유 |
|---|---|
| 담기에서는 검사하지 않는다 | [ADR 0015](../catalog/0015-no-stock-quantity-in-public-response.md)가 재고를 가렸으므로 FE가 상한을 모른다. 담아둔 뒤 **주문 단계에서야** 거절되는 것을 사용자가 감수하게 되는데, 0015가 받아들인 비용은 "담기 시점 거절"까지였다 |
| 담기 시점에 재고를 예약한다 | 담아두고 사지 않는 사용자가 재고를 묶는다. 만료 해제 배치가 따라오고, 그 배치가 없으면 재고가 영구히 샌다. 장바구니는 체류 시간에 상한이 없다 |
| 점유를 결제 성공(`PAID`)으로 미룬다 | `PENDING` 주문 여러 건이 같은 마지막 재고를 두고 결제에 진입한다. **결제가 성공한 뒤에 재고 부족을 알리는 것**이 최악이다 |
| 담기 검사만 두고 주문에서는 믿는다 | 담기와 주문 사이에 재고가 줄어도 거를 수 없다. 음수 재고는 복구가 아니라 버그다 |

## 결과 / 되돌리려면

- ⚠️ [ADR 0015](../catalog/0015-no-stock-quantity-in-public-response.md) 본문은 담기 거절을
  `P002`로 적었다. 담기는 `decreaseStock()`을 호출하지 않으므로 그 경로의 코드는 `CT002`다.
  **0015의 전제는 그대로 유효하므로 대체하지 않는다** — 코드 이름만 이 ADR이 정정한다
- `PENDING` 주문이 결제되지 않으면 재고가 계속 점유된다. 장바구니 예약을 배제한 이유가
  범위만 좁혀 재현되므로 **만료 처리를 정해야 한다** — [roadmap.md](../../roadmap.md)
- **되돌리는 비용이 크다.** 점유 시점을 옮기면 Cart·Order·Payment 셋의 규칙이 함께 바뀐다
- 동시성 제어 방식(비관적 락 / 낙관적 락+재시도 / 원자적 감소)은 이 ADR이 정하지 않는다.
  `P002`가 유일한 방어선이라는 것만 고정한다
