## Q. Review 도메인 구현

**목적**: 배송 완료 상태 주문에 한해 리뷰를 작성하고, 중복 작성을 방지하며, 상품별 평균 평점을 집계한다.

**개발 방향**
- 리뷰 작성 자격 조건(주문 상태가 배송완료여야 함)을 어느 시점에 검증할지 — 이미 `ErrorCode.REVIEW_NOT_ALLOWED`가 정의되어 있으므로, 서비스 계층에서 주문 상태를 확인한 뒤 예외를 던지는 흐름으로 설계.
- 동일 주문(혹은 동일 주문 항목)에 대한 중복 리뷰 작성을 막는 검증 — `ErrorCode.REVIEW_ALREADY_EXISTS` 활용. 주문 단위로 막을지, 주문 내 개별 상품 단위로 막을지 결정 필요(한 주문에 여러 상품이 있을 수 있으므로).
- 상품 상세 조회 응답에 평균 평점을 포함시킬지, 어떤 방식으로 집계할지(매 조회 시 실시간 집계 vs 상품 엔티티에 캐시된 값 유지) 성능 관점에서 결정.
- 리뷰 수정/삭제는 작성자 본인만 가능하도록 제한 — `ErrorCode.FORBIDDEN`을 활용해 본인 확인 로직을 서비스 계층에 둘 것.
- 리뷰 이미지 첨부 여부와 저장 방식은 Product 도메인([[phase3-category-product]] M 항목)의 이미지 저장 방식과 일관되게 결정.

**체크포인트**

- [ ] 동일 주문에 대한 중복 리뷰 작성 시 거부(409)
- [ ] 상품 상세 조회 시 평균 평점이 포함되는지 확인
- [ ] 본인이 작성하지 않은 리뷰 수정/삭제 시도 시 거부
