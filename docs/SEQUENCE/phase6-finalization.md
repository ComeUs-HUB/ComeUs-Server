# Phase 6 — 마무리 (R~S)

> 상태: 미구현 — 전 도메인 구현이 선행되어야 하는 단계 ([[phase2-auth]]~[[phase5-review]] 완료 후 진행)

모든 도메인 구현이 끝난 뒤, 권한 설정을 전체적으로 점검하고 회귀를 방지할 테스트를 갖추는 마무리 단계.

---

## R. RBAC 권한 설정 완성

**목적**: 전 도메인 구현 완료 후 엔드포인트별 권한을 최종 점검하고 누락된 접근 제어를 완성한다.

**목표 권한 매트릭스**

| 도메인 | 비회원 | USER | ADMIN |
|--------|--------|------|-------|
| 상품 조회 | 허용 | 허용 | 허용 |
| 상품 CRUD | 불가 | 불가 | 허용 |
| 카테고리 조회 | 허용 | 허용 | 허용 |
| 카테고리 CRUD | 불가 | 불가 | 허용 |
| 장바구니 | 불가 | 허용 | 허용 |
| 주문 (본인) | 불가 | 허용 | 허용 |
| 주문 전체 조회 | 불가 | 불가 | 허용 |
| 결제 | 불가 | 허용 | 허용 |
| 리뷰 조회 | 허용 | 허용 | 허용 |
| 리뷰 작성/수정 | 불가 | 허용(본인) | 허용 |
| 리뷰 삭제 | 불가 | 허용(본인) | 허용 |

**개발 방향**
- [[phase2-auth]] H 항목에서 구성한 필터체인 정책과 위 매트릭스가 실제로 일치하는지 엔드포인트 단위로 재점검.
- 컨트롤러/필터체인 레벨 방어 외에 서비스 레이어에도 이중으로 권한 검증을 걸지 여부 결정 — 특히 ADMIN 전용 로직과 "본인 리소스만 접근 가능" 로직(리뷰 수정/삭제 등)은 서비스 계층 방어가 유용.
- 401/403 응답이 프로젝트 공통 응답 포맷([[phase1-global-foundation]] D 항목)과 일치하는지 최종 확인.

**체크포인트**
- [ ] 권한 매트릭스 전 항목 실제 테스트 통과
- [ ] 401, 403 응답이 공통 응답 포맷 준수

## S. 테스트 코드 작성

**목적**: 핵심 비즈니스 로직의 단위 테스트와 API 레이어의 통합 테스트를 작성하여 회귀를 방지한다.

**구현 현황 — 최소 상태**

- 현재 `BackendApplicationTests`에 컨텍스트 로딩 확인용 스모크 테스트 1개만 존재.
- 다만 `src/test/resources/application.yml`에 H2 인메모리 DB 테스트 설정이 이미 준비되어 있어([[phase0-environment-setup]] C 항목 참고), 통합 테스트를 작성할 인프라 자체는 갖춰진 상태.

**개발 방향**
- 우선순위가 높은 테스트 대상을 도메인 구현 순서에 맞춰 정리: JWT 토큰 생성/검증/만료, 회원가입 이메일 중복 검증, 재고 차감 및 품절 전환, 주문 동시성 제어, 장바구니 수량 합산, 리뷰 작성 조건 검증.
- 단위 테스트(Service 레이어, Mock 기반)와 통합 테스트(Controller 레이어, MockMvc 또는 H2 기반 실제 DB 연동)를 어떤 비율로 둘지 도메인별로 결정 — 핵심 비즈니스 로직일수록 단위 테스트 우선.
- 각 도메인을 구현하는 시점에 해당 도메인 테스트를 함께 작성하는 방식(선반영)을 권장 — Phase 6까지 미루면 테스트 부채가 누적됨.

**체크포인트**
- [ ] `./gradlew test` 전체 통과
- [ ] 핵심 서비스 로직 단위 테스트 커버리지 확보
